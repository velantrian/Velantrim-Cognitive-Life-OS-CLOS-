# 🧭 CLOS Ecosystem Crosswalk

```text
Status: RESEARCH OWNERSHIP MAP
CLOS GitHub home: THIS REPOSITORY
Authority transfer: NONE
```

This dedicated repository is the primary GitHub home for **CLOS research documentation**. That does **not** make CLOS a sovereign authority over the existing Velantrim projects.

CLOS discovers and tests substrate-neutral cognitive requirements. A validated consequence moves to another project only through an explicit owner-specific crosswalk and that project's own governance.

## Admission rule for cross-project transfer

A CLOS result may be proposed to another project only if all are true:

1. **Materiality** — a concrete failure exists without the rule.
2. **Distinctness** — existing owner vocabulary cannot express the requirement without material semantic loss.
3. **Ownership** — the requirement belongs to the target project's declared responsibility.
4. **Technology neutrality** — the proposed invariant is not merely an implementation mechanism unless the target project is implementation/runtime oriented.
5. **Evidence** — the candidate has bounded fixtures or scoped supporting evidence.
6. **Authority** — target-project governance explicitly accepts it.
7. **No promotion drift** — research remains research until the owner changes its status.

```text
CLOS RESULT
≠ OWNER ADOPTION
≠ IMPLEMENTATION
≠ RUNTIME ENABLEMENT
≠ PRODUCTION AUTHORITY
```

## Examples

### Example A — candidate omission

If research establishes only:

```text
NOT SURFACED ≠ ABSENT
```

it can remain a CLOS research distinction.

If it proves to be a substrate-neutral semantic preservation obligation across replaceable memory/retrieval profiles, it may be proposed to **Native Kernel**.

If it implies a concrete Reader/source fallback or retrieval policy, implementation may belong to **Crystal** or **Titan** depending on the owning path.

### Example B — correction precedence

If the issue is preserving revised belief/self state inside cognition, **Mentaury Soul** is the first domain owner.

If the issue is handoff across model/runtime replacement, **Continuum** may own the process-continuity rule.

If the issue is immutable source/provenance/history semantics, **Native Kernel** or **Crystal** may own the corresponding boundary.

### Example C — STOP semantics

Reason-typed stopping is researched in CLOS.

A cognition-domain semantic consequence may belong to **Mentaury Soul**.

A runtime scheduler implementing it belongs to **Titan** only after a separate implementation decision.

A cross-project STOP receipt becomes a **Mentaury-Kernel** concern only if composition itself can corrupt the stop reason/status.

### Example D — event segmentation

Plural task-relative segmentation remains a CLOS bounded research question.

If a stable substrate-neutral obligation about declared alternatives/currentness/re-segmentation survives ES-02, it may crosswalk to **Native Kernel**.

If the problem is continuity of segmentation state across model replacement, it may crosswalk to **Continuum**.

Text sentence splitting in **Titan** is not automatically cognitive event segmentation.

## Dedicated repo ≠ seventh sovereign

Creating a dedicated CLOS repository changes **documentation placement**, not ecosystem authority.

```text
DEDICATED REPOSITORY
≠ NEW ROOT OF AUTHORITY
≠ OWNER OF ALL COGNITION
≠ REPLACEMENT FOR PROJECT-LOCAL GOVERNANCE
```

Most research results should remain here unless an owner-specific obligation survives crosswalk.
