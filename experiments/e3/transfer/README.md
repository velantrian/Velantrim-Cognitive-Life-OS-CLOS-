# F3 A: теряется ли просьба владельца в Titan и Crystal (проба, 2026-11-26)

**Статус: RESEARCH ONLY.** Проба выполнена на **чистых копиях** (`git archive HEAD`) `Velantrim-ExoCortex-Titan` (`ad92aa0`) и `velantrim-exocortex-crystal` (`78088e0`); оригиналы не менялись. Без LLM, без сети, без ключей. Это не разрешение на правки в соседних репозиториях (`docs/ECOSYSTEM_CROSSWALK.md`).

**Критерий:** после «паузы» (запись → закрытие → повторное чтение из хранилища) преемнику видно, что (1) результаты есть, (2) работа завершена, (3) подключение в routing в просьбу не входило.

## Результат

| Сценарий | Результаты | Завершено | Граница (routing не просили) |
|---|---|---|---|
| Titan T1 — слова владельца в `user_goal`, «вне договорённости» в `conclusion` | да | да | да → **критерий выполнен** |
| Titan T2b — короткая запись «работа завершена» | да | да | **нет** |
| Titan T2 / T3 / T4 — короткая сводка / запись без слов владельца / цель в `GoalStack` | да | нет | нет |
| Titan T5 — полная цель в `GoalStack` | да | да* | да |
| Crystal C1 — обычный ввод слов владельца и результатов | да | да | да |
| Crystal C2 — типизированные утверждения с метаданными | да | да | да |
| Crystal C2b — «завершено» без границы | да | да | **нет** |
| Crystal C3 — запись без слов владельца | да | нет | нет |

\* для T5 «завершено» засчитано по `status == done`, это голый флаг.

## Выводы

1. **При хранении информация не теряется.** В Titan проекция блокнот → эпизод нормализует только пробелы (NFC); во всех сценариях содержимое осталось полным. Crystal сохраняет текст утверждения целиком.
2. **Теряется при записи:** если автор записи не вписал слова владельца и «вне договорённости», нигде нет поля или проверки, которая это потребует (T2b, T3, T4, C2b, C3). Это тот же сбой, что у авторской записи F3 A в пилоте E3.
3. **Titan:** повторный `finalize()` без `user_goal` **стирает** просьбу владельца (проверено: после второго вызова `user_goal == ''`, `main_topic` сохраняется). В `ConversationEpisode` и `GoalStack` нет поля для границы договорённости; `status=done` — флаг. `key_insights` режутся до 300 знаков.
4. **Crystal:** при обычном вводе просьба владельца сохраняется целиком, но с типом `WORLD_FACT` и состоянием `Validated`; выводы исполнителя (`source="executor"`) получили `source_status=USER_REPORTED`, то есть по умолчанию владелец и исполнитель не различаются. Различие появляется только при ручном задании типов и ролей (C2).

## Предложения (не применены; решает оператор, правит владелец репозитория)

- **Titan:** `finalize()` не перезаписывает `user_goal` пустым значением; обязательные разделы записи «Просьба владельца (дословно)», «Вне договорённости», «Сделано / не сделано»; в `ConversationEpisode` необязательные поля `owner_words` и `out_of_scope`.
- **Crystal:** конвенция ролей в `metadata` (`task`, `role` ∈ `owner_request` / `scope_exclusion` / `result` / `state`) и проверка наличия `owner_request`; отдельно разобраться с типизацией просьбы как `WORLD_FACT`/`Validated` и выводов исполнителя как `USER_REPORTED`.

## Оговорки

- Единицы информации определены **по ключевым словам** (поиск «48» и «180», фраз о завершении и «вне договорённости»/«менять не будем»); это поисковая проверка.
- Тексты сценариев писал автор пробы. Это проверка того, что системы **сохраняют и чего требуют**, а не измерение поведения реальных агентов; LLM-преемник не участвовал.
- Один сценарий (F3 A). Crystal запускался в тестовой конфигурации (`VELANTRIM_L3_BACKEND=mock`, хэш-эмбеддер, `VELANTRIM_DEMO_SEED=1`).
- Утверждение разведки, что у `ConversationConsolidator` нет вызывающего кода в продакшене, не проверялось.
- Сторонние репозитории в этот репозиторий не копируются.
